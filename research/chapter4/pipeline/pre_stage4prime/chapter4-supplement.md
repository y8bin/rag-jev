# 제4장 보충 자료

이 자료는 [제4장 본문](chapter4.md)의 평가·집계 방식과 사례 선정 상세를 제공한다. 새로운 실험이나 모델 호출은 없다. 수정 단계에서 기존 원자료로 추가 산출한 구간과 기술통계는 결과를 관찰한 뒤 계산한 탐색적 값이며, 산출 코드와 출력은 `scripts/chapter4_revision_analysis.py`와 `results/koblex-reproduction-v1/chapter4-revision-v1/`(`revision-analysis.json`, `shortlist-bootstrap.json`)에 있다.

## S1. 평가 절차와 지표 정의

예상 법령은 질문과 배경을 바탕으로 모델이 생성한 검색용 법령 문구이며, 평가 자료가 제공한 정답 근거(gold)와 구별된다. 각 예상 법령을 이용해 corpus에서 BM25 후보 100개를 검색하고, 원 질문과 후보 법령을 CE(`dragonkue/bge-reranker-v2-m3-ko`) 또는 Jev로 점수화하여 상위 10개 shortlist를 구성하였다. Jev에는 잠금 파일(`protocol-lock.json`의 `jev_instructions`)에 기록된 관련성 지시문 "Rank by relevance: does the candidate statutory passage directly support answering the question?"이 주어졌고, CE에는 지시문이 없다. LLM은 목록마다 하나를 선택하고, 선택 근거를 답변 생성 모델에 제공하였다. 서로 다른 목록에서 같은 근거를 선택할 수 있으므로 선택 항목 수와 고유 근거 수는 다를 수 있다.

근거 평가는 문항별로 최종 선택 근거와 gold의 문자열 집합을 비교한다. 중복 문자열은 한 번만 센다. 정밀도는 선택 근거 중 gold의 비율, Recall은 gold 중 선택된 비율이며 F1은 두 값의 조화평균이다. EM은 두 집합의 완전 일치 여부이고, 완전 회수는 gold가 선택 집합에 모두 포함되는지를 나타낸다. F1·Recall은 문항별 점수의 비가중 평균으로 0–100 척도의 점으로, EM·완전 회수율은 해당 조건을 충족한 문항의 비율로 %와 %p로 표기한다.

예를 들어 gold가 A·B인 문항에서 A만 선택하면 부분 회수이다. A·B·C를 선택하면 완전 회수이지만 EM은 충족하지 않는다. A·B만 선택해야 완전 회수와 EM을 모두 충족한다.

### CE 입력 형식 진단

CE 입력 형식은 평가 문항 30개(hop별 사전순 첫 10개, `ce-diagnostic-plan.json`)에서 네 가지 입력 형식(배경 포함 여부, 법령 표기 방식)을 비교한 탐색적 진단(`ce-diagnostic-summary.json`) 후 원 질문만 사용하는 형식으로 정하였다. 이 진단은 미노출 시험이 아니다. 선택된 형식은 공식 코드의 재정렬 입력(`selection_retrieval.py`의 `rerank()`가 원 질문과 `hierarchy + content` 문자열을 쌍으로 입력)과 같다. 진단의 CE 근거 F1은 원 질문 형식 33.94점, 배경 포함 형식 17.94점과 18.09점이었으므로 이 선택은 CE에 유리한 방향이며, Jev에도 같은 입력을 적용하였다. 진단 30문항을 제외한 196문항(139개 그룹)에서 Jev−CE 차이는 근거 F1 +3.34점(CI [+0.68, +6.07]), LF-Eval +2.66점(CI [+0.26, +5.05]), Token F1 +1.26점(CI [+0.04, +2.49])이었다.

### 답변 지표

Token F1은 정규화한 생성 답변과 정답 답변을 공백 단위로 나누어 토큰 중복을 측정한다. 사용량 토크나이저의 토큰과는 다른 단위이다. 한국어의 공백 단위는 조사·어미가 붙은 어절이므로 같은 개념도 형태가 다르면 다른 토큰이 되며, 소폭의 차이는 표현 형태의 변화를 포함한다. 두 자동 평가 모두 공식 코드의 처리 규칙에 따라 생성 답변을 전처리하고 앞 800자까지 사용하였으나, 세 조건 모두 800자를 넘는 답변은 0개였다.

LF-Eval은 LLM 평가기가 공식 정답 답변과 gold를 기준으로 답변의 법률적 정확성, 누락, 모순 등을 평가한다. 평가 기준(`research/prompts/koblex_lf_eval.json`의 `criteria`)은 10점을 "the response correctly and thoroughly uses all of the given legal provisions"로 정의하고, context의 요소를 누락하면 크게 감점한다. 따라서 gold를 더 많이 회수한 답변이 유리할 수 있어 LF-Eval은 근거 회수와 독립적인 지표가 아니다. 문항별 근거 F1 차이와 LF-Eval 차이의 Pearson 상관은 0.53이었다. LF-Eval 평균 차이 +2.58점은 선택 근거 집합이 CE와 같은 119문항에서 0점, 집합은 다르지만 근거 F1이 같은 58문항에서 +0.85점, 근거 F1이 달라진 49문항에서 +1.74점이 기여한 합이다. 근거 F1이 같은 58문항에서도 LF-Eval은 Jev 34문항 상승, 17문항 하락이었으며, 이는 정답 외 근거의 차이나 생성 변동을 함께 반영할 수 있다. 생성기와 평가기는 모두 `gpt-4o-2024-08-06`이지만 두 조건의 답변이 같은 모델에서 생성되므로, 평가기의 선호가 있다면 두 조건에 대칭적으로 작용한다. LF-Eval은 실제 시스템이 제공한 근거를 기준으로 한 주장 지지 평가와도 구별된다.

`identical-answer-judge-audit.json`의 동일 문항·동일 답변 272쌍은 모두 같은 평가 요청 digest를 가지며 저장된 평가 응답을 재사용한 것이다. 따라서 이 점검은 집계 일관성 확인이며, 같은 입력에 대한 평가기 재호출의 재현성은 별도로 검증하지 않았다.

### 신뢰구간과 다중성

신뢰구간은 같은 출처나 gold를 공유하는 문항을 묶은 151개 의존 그룹에 대해 산출하였다. 각 문항의 두 조건 결과를 짝지은 채 그룹 단위로 복원추출하는 대응 bootstrap을 10,000회(seed 20261108) 수행하고, 차이 분포의 양끝 2.5%를 제외한 percentile 구간을 사용하였다. 문항별 점수는 동일 가중치로 집계한다. 수정 단계에서 추가한 구간(4.3의 shortlist Recall·모든 gold 유지 문항 비율, 이 절의 Precision과 진단 문항 제외 민감도)은 결과를 관찰한 뒤 같은 코드(`legal_rag_jev.koblex_analysis.paired_bootstrap`)와 같은 그룹·반복 수·seed로 산출한 탐색적 구간이다. 산출 전에 같은 코드로 `analysis.json`과 필터링 `e2e-summary.json`의 저장 구간 26개를 모두 같은 값으로 재현하여 절차의 동일성을 확인하였다.

비교 계열은 Jev와 CE의 F1, Recall, EM, 완전 회수, Token F1, LF-Eval의 6개로 정의한다. Precision은 F1이 P와 R의 함수이고 잠금 분석에 p값이 없어 계열에서 제외하며, 참고로 차이는 +3.39점(CI [+0.77, +6.02])이다. 아래 p값은 저장된 centered-bootstrap 양측 p값이고, 이 p값은 percentile 구간과 같은 방식으로 구성한 구간·검정 쌍이 아니다. Holm·BH 보정은 참고용이며 본문 해석은 무보정 구간을 가설 생성적 근거로만 사용한다.

| 지표 | 차이 | 무보정 p | Holm | BH |
| --- | --- | --- | --- | --- |
| 근거 F1 | +3.19점 | 0.012 | 0.074 | 0.050 |
| Recall | +2.95점 | 0.025 | 0.113 | 0.050 |
| EM | +1.77%p | 0.348 | 0.696 | 0.418 |
| 완전 회수 | +0.88%p | 0.678 | 0.696 | 0.678 |
| Token F1 | +1.12점 | 0.052 | 0.157 | 0.079 |
| LF-Eval | +2.58점 | 0.023 | 0.113 | 0.050 |

Holm 보정 후 0.05 수준에 남는 지표는 없고(최소 0.074), BH 보정 q값은 F1·Recall·LF-Eval이 0.0496이다. 공개 코드 CE 대비 수정 CE의 같은 6개 지표 p값은 모두 0.0004 이하였다. Token F1 구간 하한(+0.02점)은 Monte Carlo 변동에 민감하다. 같은 절차를 seed 20261109–20261128의 20개로 반복하면 하한은 −0.05~+0.03점이었고 20개 중 12개에서 0보다 작았다. 보고 구간은 잠금 seed의 값을 유지하며, 본문은 이 결과를 경계적으로 서술한다.

## S2. 공개 코드의 후보 목록 참조 문제와 세 조건

공개 코드는 여러 후보 목록에 대한 LLM 선택 결과를 처리할 때 현재 목록 대신 항상 첫 번째 목록의 같은 번호를 참조한다(`contexts_list[0][choice]`). CE와 Jev 조건은 현재 목록에서 선택된 번호를 읽도록 수정하였다. 공개 코드 CE는 원래 동작을 보존한 참조이며, CE는 후보 목록 참조 방식을 수정한 주 기준선이다. 따라서 공개 코드 CE와 CE의 차이는 이 문제의 수정에 따른 변화이고, CE와 Jev의 차이가 모델 교체의 주 비교이다.

| 지표 | 공개 코드 CE | CE(수정) | Jev |
| --- | --- | --- | --- |
| Precision | 57.23 | 63.46 | 66.85 |
| Recall | 45.35 | 57.74 | 60.69 |
| 근거 F1 | 48.72 | 58.57 | 61.75 |
| EM(%) | 17.70 | 27.88 | 29.65 |
| 완전 회수(%) | 20.80 | 34.07 | 34.96 |
| Token F1 | 40.70 | 46.20 | 47.31 |
| LF-Eval | 58.30 | 67.57 | 70.15 |

값은 `results/koblex-reproduction-v1/analysis.json`의 `summaries`이다. 수정 CE−공개 코드 CE 차이는 근거 F1 +9.85점(CI [+6.85, +13.02]), Recall +12.39점(CI [+9.28, +15.83]), EM +10.18%p(CI [+4.70, +15.86]), 완전 회수 +13.27%p(CI [+8.62, +18.34]), Token F1 +5.49점(CI [+3.78, +7.30]), LF-Eval +9.27점(CI [+6.20, +12.30])이었다(같은 파일의 `comparisons`). 확인 대상은 공개 코드 스냅샷이며, 원 논문의 실제 실행에도 같은 문제가 있었다고 판정한 것은 아니다.

## S3. 자원 사용량과 캐시의 집계

문맥 토큰은 실제 선택 목록의 순서와 중복을 유지하고 줄바꿈으로 연결한 문자열에 `o200k_base` 토크나이저를 적용해 산출하였다. 전체 API 입력·출력량은 생성 응답의 사용량 기록에서 가져왔다. 전체 입력에는 선택 근거 외에 질문·지시문·예시가 포함된다. IQR은 제3사분위수와 제1사분위수의 차이로, 가운데 절반의 값이 퍼진 폭을 나타낸다.

저장된 생성 응답을 재사용한 문항은 CE 72개, Jev 122개였다. 생성 입력(질문과 선택 근거 문자열)이 앞서 실행한 조건과 같으면 저장 응답을 재사용하였다. Jev 122개 중 121개는 CE와, 1개는 공개 코드 CE와 생성 입력이 같았다. CE와 선택 행 집합이 같은 문항은 119개이고, 행 번호는 다르지만 같은 조문 문자열을 가진 corpus 중복 행을 선택한 2문항을 더하면 생성 입력이 같은 문항은 121개이다. 이 121문항의 답변 지표 차이는 0이며, 답변 문자열이 같은 문항은 124개였다. 따라서 Jev와 CE의 답변 지표 차이는 답변이 다른 102문항에서만 발생한다. 재사용 문항도 동일 입력과 답변에 해당하는 토큰량을 포함하여 집계하였다. 본문의 사용량은 조건별 요구량이며 이번 실행의 신규 청구액이 아니다. 점수화·평가·재시도와 로컬 CE 운영비를 포함한 독립 서비스 비용은 산출하지 않았다. 실행 시간에는 캐시와 요청 제한 대기가 포함되어 응답 지연의 공정한 비교에 사용할 수 없다.

## S4. 관측 유형과 사례 선정

단계별 집계에서는 한 문항 안의 고유 gold를 한 번씩 세고, 같은 gold가 다른 문항에도 필요하면 각 문항에서 따로 센다. 이 방식의 출현은 조건별 443건이며, 전체 문항에서 중복을 제거한 고유 gold 386개와 구별된다. 각 출현은 최초 탈락 단계 또는 최종 선택 상태 하나에만 배정하였다. 반면 한 문항에는 여러 관측 유형이 겹칠 수 있으므로, 문항별 관측 유형 빈도의 합이 전체 오류 문항 수를 뜻하지는 않는다.

사례 A는 근거 F1이 Jev에서 개선된 집단, B는 CE가 높은 집단, C는 근거 F1과 답변 Token F1 또는 LF-Eval이 엄격히 반대 방향으로 변한 집단에서 선정하였다. 각 집단의 근거 F1 차이 절댓값 중앙값에 가장 가까운 문항을 택하였으며, 동률이면 query_id의 사전순으로 정하였다. 선정된 C는 근거 F1과 Token F1의 불일치 사례이다. 사례 A는 CE 입력 형식 진단에 쓰인 30문항에 포함되고, B와 C는 포함되지 않는다.

| 사례 | 문항 식별자 | 관측 유형 |
| --- | --- | --- |
| A | `qa_124_2hop_480_rand` | Jev 개선 |
| B | `qa_324_2hop_515` | CE 우세 |
| C | `qa_443_3hop_703` | 근거 F1 감소·Token F1 증가 |

세 사례의 배경·질문, gold 조문, 조건별 선택 조문과 생성 답변 원문은 `results/koblex-reproduction-v1/chapter4-prep-v1/A6/casebook.jsonl`의 해당 `query_id` 행(`background`, `question`, `gold_provisions`, `reference_answer`, `conditions`)에 있다. 자동 평가기의 설명은 법률 판정으로 사용하지 않았으며, 사례 분석은 자동 관측에 근거하고 정답 외 조문의 법률적 적절성은 판정하지 않았다. 사례 C에서 Jev가 선택한 정답 외 조문은 형법 제39조제3항과 사면법 제5조제1항이다.

corpus 미매핑 고유 gold 27개(29문항)는 모두 같은 법률·조·표제(`hierarchy`)를 가진 corpus 행이 있었다. 27개 중 26개는 corpus 행 문자열이 gold 문자열의 앞부분과 같았고, 25개는 gold 안에 줄바꿈으로 이어진 각 호 목록이 포함되어 있었다. 공백 정규화로 일치하는 경우는 없었다. 즉 미매핑은 해당 조문이 corpus에 없는 경우라기보다 gold가 조 본문과 각 호를 한 문자열로 담고 corpus는 이를 나누거나 생략한 구획 차이에서 비롯된 것으로 보이며, 두 조건에 같게 작용한다.

1·2·3-hop의 Jev−CE F1 차이는 각각 −1.17점, +3.91점, +6.92점이었으며, 전체 F1 차이 합에서 차지하는 비율은 −9.3%, 68.9%, 40.3%였다. 1-hop의 감소는 57문항 중 1문항에서 왔다. 문항별 동률은 반올림 전 차이에 10⁻¹²의 허용오차를 적용하여 판정하였다. 같은 출처나 정답 근거를 공유하는 문항을 포함하므로 개선·동일·악화 개수를 독립 시행의 성공률로 해석하지 않았다. 3-hop에서 Jev는 shortlist에서 모든 gold를 동시에 선택할 수 있는 문항을 2개에서 11개로 늘렸지만 완전 회수는 두 조건 모두 1/42문항이었다. 예상 법령 목록 수가 gold 수보다 적은 문항은 목록당 하나를 선택하는 절차로 완전 회수가 처음부터 불가능하며, 그 수는 두 조건에서 같다.

사례 C는 정답 근거 3개에 대해 생성된 후보 목록이 2개였으므로, 목록당 하나를 선택하는 현재 절차로는 정답 근거 전부를 선택할 수 없었다. 사례 A의 CE 선택 근거에는 식품위생법 제42조제2항과 생산실적 관련 시행규칙이 포함되었으며, Jev는 제42조제2항과 제45조제1항을 선택하였다. 사례 B에서 두 조건의 공통 정답 선택 근거는 민사소송법 제253조였다.

## S7. 선택 후 필터링과 답변 재생성

본문 표 2의 근거 지표는 `results/koblex-filtering-v1/summary.json`의 `cv_overall`과 대응 bootstrap, 답변 지표와 완전 회수는 `e2e-summary.json`에 근거한다. 의존 그룹 151개를 5-fold로 나누었으며 seed는 20261109이다. 각 scorer의 학습 fold 점수 분위수로 유지율 1.00~0.05의 20개 격자를 구성했다. 학습 fold의 F1이 원래 값보다 1점 넘게 낮아지지 않는 후보 중 유지 근거 수가 가장 적은 문턱값을 선택하여 검증 fold에 적용했다. 학습 fold의 허용 하락폭은 검증 fold의 성능 보장이나 비열등성 한계 검정이 아니다.

**격자 변경 이력.** 처음에는 두 scorer에 같은 0.00~0.95 절대 격자를 적용했다. 그러나 CE가 선택한 근거의 점수는 대부분 0.05 미만이어서 CE 필터링이 사실상 불가능했고, 이 결과를 확인한 뒤 기존 설계 문서의 척도별 격자(같은 크기) 원칙에 따라 scorer별 분위수 격자로 바꾸었다(`results/koblex-filtering-v1/README.md`의 수정 이력, `scripts/simulate_koblex_filtering.py` 머리말). 저장 기록은 격자 변경만 수정 이력으로 남기며, 허용 하락폭 1점·20개 격자·최소 유지 목적함수가 첫 실행 전에 정해졌다는 별도 기록은 없다. 따라서 이 선택들도 결과 관찰 후의 분석 선택으로 취급한다.

CE의 fold별 문턱값은 0 또는 약 0.0000037~0.0000038, Jev는 0.30~0.40이었다. 검증 fold 통합 유지율은 CE 467/478=97.70%, Jev 426/478=89.12%였고, 근거가 하나도 남지 않은 문항은 CE 1개, Jev 4개였다. 이미 본 평가 문항 안의 탐색적 교차검증이므로 미노출 외부 시험을 대신하지 않는다. bootstrap 구간 역시 비열등성 입증으로 사용하지 않는다.

필터링 후 완전 회수율은 CE+필터링과 Jev+필터링이 모두 33.19%로 같아졌다. 각 조건 안의 차이(필터링−필터링 전)는 다음과 같다.

| 지표 | CE+필터링−CE | Jev+필터링−Jev |
| --- | --- | --- |
| 근거 F1 | −0.03 [−0.60, +0.45] | −0.32 [−1.76, +1.07] |
| Precision | +1.11 [+0.33, +2.07] | +2.95 [+1.05, +5.01] |
| Recall | −0.59 [−1.35, 0.00] | −2.43 [−3.81, −1.16] |
| 완전 회수(%p) | −0.88 [−2.29, 0.00] | −1.77 [−3.51, −0.43] |
| Token F1 | −0.54 [−1.19, −0.07] | −0.28 [−1.10, +0.44] |
| LF-Eval | −0.44 [−1.22, +0.14] | −1.02 [−2.23, +0.15] |

CE+필터링의 Token F1 차이(−0.54점)는 답변이 바뀐 10문항에서만 발생하므로, 구간 경계가 0에 가까운 다른 지표와 마찬가지로 방향만 기술한다. 재생성 답변의 차이에는 필터링 효과와 단일 재생성의 변동이 섞여 있으며, 같은 입력은 저장 응답을 재사용했으므로 생성 변동의 기준선은 이 자료로 추정할 수 없다.

조건 간 비교에서 Jev+필터링−CE+필터링은 근거 F1 +2.89 [+0.26, +5.60], 완전 회수 0.00 [−4.02, +4.00]%p, Token F1 +1.38 [+0.09, +2.69], LF-Eval +2.00 [−0.36, +4.32]였고, Jev+필터링−필터링하지 않은 CE는 근거 F1 +2.86 [+0.24, +5.54], 완전 회수 −0.88 [−4.85, +3.11]%p, Token F1 +0.83 [−0.39, +2.00], LF-Eval +1.56 [−0.83, +3.86]였다. 두 scorer의 실제 필터링 강도(유지율 97.70%와 89.12%, 재생성 10문항과 45문항)가 달라 이 비교는 같은 조건의 필터링 대 필터링 비교가 아니다. 같은 비율을 유지하는 기술통계(`post_matched_keep_rate.csv`)에서 근거를 90% 유지할 때 F1은 CE 57.21, Jev 61.66이었다.

`pre_matched_keep_rate.csv`는 선택 전 shortlist 후보를 제거했을 때 문항별 gold 출현 443건 기준의 유지 비율을 계산한다. 후보를 약 절반으로 줄일 때 유지 비율은 CE 66.14%(293/443)→51.47%, Jev 72.69%(322/443)→69.30%였다. 이 분모는 문항별 평균 Recall의 분모와 다르며, 선택 전 필터링에서는 LLM 선택을 다시 실행하지 않았으므로 최종 선택·답변 결과를 뜻하지 않는다.

선택 후 필터링의 답변 재평가는 `e2e/`의 예측·LF-Eval 결과(조건별 226행)에 근거한다. 위 교차검증 문턱값은 근거 F1만으로 답변 생성 전에 정했고 이후 바꾸지 않았다. 유지 근거가 원 선택과 달라진 문항(CE 10개, Jev 45개)만 주 실험과 같은 답변 프롬프트와 `gpt-4o-2024-08-06`으로 재생성했으며, 근거가 모두 제거된 문항은 빈 문맥으로 생성했다. 나머지 문항(CE 216개, Jev 181개)은 생성 입력이 같으므로 원 답변을 재사용했고, 재사용 문항의 LF-Eval 점수가 원 실험과 같음을 확인했다. 차이의 구간은 같은 151개 그룹의 대응 bootstrap 10,000회(seed 20261108)로 산출했다. 비열등성 마진을 사전에 정하지 않았으므로 이 구간은 품질 유지나 동등성의 근거로 사용하지 않는다. 필터링에 따른 실제 비용·지연 변화는 측정하지 않았다.

## S9. 완료된 재정렬 지연 벤치마크

출처는 `results/koblex-latency-v1/protocol.json`, `raw.jsonl`, `summary.json`, `completed.json`이다. hop별 층화 무작위 추출(seed 20261108)로 사전에 고정한 60문항 표본(1/2/3-hop 15/34/11)을 사용했으며, 이는 연구 전체의 사전확증 실험이나 사전등록을 뜻하지 않는다. 캐시를 사용하지 않고, 각 방법의 워밍업 3문항을 제외한 360개 본 측정을 집계했다. 문항과 방법 순서는 seed 20261109로 무작위화했으며 두 방법을 동시에 실행하지 않았다. 질문–후보 쌍은 문항 내 법령 문자열 중복을 제거하여 두 방법에서 같게 구성했다. 문항별 후보 쌍은 평균 176.98개(83~287개)였다.

각 문항의 방법별 세 번 지연을 평균하여 문항당 하나의 관측값을 만들었다. 표 1의 중앙값 및 제95백분위수는 이 60개 평균값의 분포에서 계산한 것으로, 개별 요청의 응답시간 분포가 아니다. Jev−CE 차이는 원래 source/gold 그룹 중 이 표본에 해당하는 52개 그룹의 대응 percentile bootstrap 10,000회(seed 20261108)로 평가했다. Jev/CE 기하평균 비율의 구간은 문항별 시간 비율의 로그에서 같은 bootstrap을 수행한 뒤 지수 변환했다. 이는 평균 시간의 단순 비율과 구별된다.

같은 60문항에서 기존 품질 실행의 Jev−CE 차이는 근거 F1 +1.39점, LF-Eval +0.87점, Token F1 +0.47점이었다(기술통계, 226문항에서는 +3.19점, +2.58점, +1.12점). 따라서 지연 표본에서의 품질 차이는 전체보다 작았으며, 본문은 226문항의 품질과 60문항의 지연을 하나의 비율로 결합하지 않는다.

CE는 로컬 Apple M5 Pro의 MPS, float32, batch 50이고 Jev는 원격 API, 동시 요청 4개였다. 동시 요청 수 4는 품질 실행의 설정(`runtime-settings.json`)과 같게 둔 값이다. 후보 쌍당 평균 지연은 CE 27.60ms, Jev 60.22ms였고, Jev의 쌍당 지연은 문항 간 거의 일정하여(사분위 59.19~60.93ms) 문항당 지연은 후보 쌍 수에 거의 비례하였다. 2.25배라는 비율은 하드웨어(예: 서버 GPU에서 CE 실행)와 Jev 동시 요청 수에 따라 어느 방향으로도 달라질 수 있다. 측정은 고유 후보 점수화와 pool별 정렬/top-10 구성을 포함한다. 예상 법령 생성, BM25, LLM 선택, 답변 생성, 모델 로드는 제외했다. 따라서 한 네트워크 세션의 배포 환경 비교이며, 모델 고유 속도 또는 전체 서비스 응답시간으로 확장하지 않는다.

파이프라인은 문항마다 예상 법령 생성 1회, 후보 목록별 LLM 선택(평균 2.12회, 코드상 순차 실행), 답변 생성 1회의 LLM 호출을 수행한다. 품질 실행 기록의 호출별 `latency_ms`는 동시 요청 제한의 대기와 재시도 대기를 포함하도록 측정되어(`src/legal_rag_jev/providers.py`) 순수 호출 시간이 아니므로, LLM 단계 지연의 참고치로 사용하지 않았다.

기존 품질 실행 대비 완전 일치는 각 문항의 모든 pool에 대해 top-10 row ID 목록과 순서가 동일한지 비교했다. CE는 180/180회, Jev는 2/180회였다. 집합 겹침은 각 pool의 두 top-10 row ID 집합 교집합 크기를 10으로 나누고, pool들을 문항 내 평균한 후 180회에서 평균한 값이다. Jev의 평균은 0.9150925926이며, 문항–반복 단위 최솟값은 0.60, 하위 10% 값은 0.85였다. 겹침이 1.00인 경우는 35회, 0.85 이하인 경우는 36회였다. `raw.jsonl`에는 반복별 top-10 row ID 목록이 저장되어 있지 않아, 어떤 gold가 shortlist 안팎을 오갔는지는 이 자료로 계산할 수 없다. 품질 실행의 Jev 점수화는 점수 캐시 파일의 수정 시각 기준 2026-11-09 02:05~02:43 UTC, 지연 측정은 같은 날 13:05~13:53 UTC에 수행되었다. 같은 모델 이름 아래 서비스가 바뀌었는지는 확인할 수 없으므로, 관측된 불일치가 호출 간 비결정성인지 시점 간 서비스 변화인지는 이 자료로 구분할 수 없다. 이 결과만으로 변화가 동률 순서 변경인지 모든 관련도 값의 변화인지 단정하지 않으며, 후속 답변을 재생성·재평가한 것으로 취급하지 않는다.

문항별 반복 지연 변동계수의 평균은 CE 16.93%, Jev 3.43%였다. 이는 후보 재현성과 다른 개념이다. Jev 본 측정의 API 비용은 0.6100542달러(180회, 후보 31,857쌍)로, 문항 1회 점수화당 약 0.0034달러, 후보 1,000쌍당 약 0.019달러이다. 워밍업·기타 단계·로컬 CE 장비 및 전력 비용을 포함한 총비용 비교가 아니다. 실제 실패와 재시도는 0건이다.
