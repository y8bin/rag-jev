현재 결과는 **원 ParSeR 절차의 수정된 CE 기준선에 비해 Jev 교체가 근거 F1과 자동 법률 충실도에서 소폭 개선되는 방향**을 보였다. 세 조건은 같은 원 ParSeR 구조 안에서 비교했다.

## CE 입력 통제 진단

기존 KOBLEX 준비 단계는 `background + question`을 하나의 질문 필드로 저장했고 일반 RAG의 CE 제공자는 이를 JSON으로 직렬화해 입력했다. 원 공개 코드는 CE에 **원 질문 문자열만** 넣는다.

같은 후보20개·N5를 고정한30문항 진단에서 기존 입력의 근거 F1은17.94점, 원 질문/원 법령 입력은33.94점이었다. 법령을 JSON으로 감싼 경우에도 질문만 입력한 점수는33.94점이었다. 배경+질문 문자열/원 법령 입력은18.09점이었다. 질문만 입력하면 배경 포함 문자열 대비17문항 개선,11문항 동일,2문항 악화였다. 이 표본에서는 배경 포함이 주요 성능 저하 요인으로 나타났으며 다른 데이터·모델에 일반화하지 않는다.

CE의 내림차순 정렬은 정상이다. CPU/MPS8쌍 점검의 최대 점수 차이는4.38e-8이었고 고유 법령 순위는 같았다. 새 본실험47,800쌍에서 CE 입력 최대 길이는1,420토큰으로8192 한도를 넘긴 입력은0개였다.

입력 효과의 근거는 위의 통제 진단이다. 아래 본실험 점수에는 원 ParSeR 검색·후속 선택 단계도 포함된다.

## 이번에 실행한 방법

원 배경+질문 → 원 프롬프트로 예상 법령 문구478개 생성 → 예상 법령별 BM25 100개 검색 → 원 질문/법령 문자열로 CE 또는 Jev 점수화 → 상위10개 중 같은 LLM이 하나 선택 → 같은 GPT-4o로 답변 → 공식 근거 문자열·Token F1·LF-Eval 평가.

원 corpus233,544행의 순서와 중복23,980행을 유지했다. CE/Jev에는 같은 후보 행과 같은 질문·법령 정보를 제공했다. 선택 수를 N5로 고정하지 않았고, 정답 hop 수로도 정하지 않았다. 생성·선택·평가 모델은 고정 GPT-4o snapshot, CE는 한국어 BGE reranker 고정 revision, Jev는1.14.0이다. 날짜·관할 필터는 원 방식처럼 추가하지 않았다.

| 조건 | 역할 |
|---|---|
| 공개 코드 CE | 원 공개 코드의 선택 인덱스 오류를 보존한 참조 |
| 수정 CE | 인덱스 오류만 수정한 주 기준선 |
| Jev 교체 | 수정 CE 파이프라인에서 점수화 단계만 Jev로 교체 |

공개 코드의 선택 결과 처리는 여러 후보 목록을 LLM에 제시한 뒤에도 항상 `contexts_list[0][choice]`를 읽는다. 수정 조건은 현재 목록의 같은 선택 ID를 읽는다. 원 코드와의 함수 비교 테스트로 오류를 재현했다. 두 CE 조건은 같은 LLM 선택 응답을 공유한다.

이 수정으로226문항 중 근거 목록154개, 고유 근거 집합153개, 최종 답변147개가 달라졌다. 수정 CE의 근거 F1은 오류 보존 참조보다9.85점, LF-Eval은9.27점 높았다. **이는 공개 코드의 오류 영향이며 원 논문의 실제 실행도 같은 오류를 포함했다는 증거는 아니다.**

## 재현 범위와 해석

- 원 입력·프롬프트·BM25/CE/LLM 선택 절차·평가 계산을 재현했다. 과거 미고정 패키지, 원 CUDA 장비, 과거 모델 응답까지 동일하다는 뜻은 아니다. 현재 장비는 MPS이며 revision과 패키지를 고정했다.
- 기존 시험 결과를 이미 확인한 뒤 수행했다. 이번 결과를 미노출 시험의 사전확증 실험으로 부르지 않는다. 점수에 따라 K/N·지시문·문항을 최적화하지 않았다.
- LF-Eval은 정답 근거를 기준으로 평가한다. 실제 제공 근거의 주장 지지 여부는 별도 사람 평가로 확인해야 한다.
- 같은 질문의 평가 대상 답변 문자열이 동일한 조건 쌍272개에서 LF 점수도 동일함을 확인했다. 조건 간 judge 캐시의 동시 쓰기를 잠금으로 막았다.
- 새 품질 실행 시간은 캐시/호출 공유를 포함하므로 지연 벤치마크로 사용하지 않는다. API 실행 지출을 전체 운영비나 방법별 독립 서비스 비용으로 해석하지 않는다.
