# 제4장 집필 계획 — 2026-11-09

상태: **계획서만 작성. 논문 본문·표·그림·오류 사례 원고는 아직 작성하지 않음.**
기준: 현재 ParSeR 재현 실험의 고정 결과. 추가 모델/API 호출, 새로운 지연 실험, 추가 지표 집계는 이 계획 단계에서 수행하지 않았다.

**사용자 수용 및 인계:** 사용자는 이 계획을 기본 방향으로 진행하기로 했다. 최종 제목/RQ 문구와 팀 조율 사항은 미확정으로 구분한다. 새 세션은 [세션 인계 문서](../SESSION_HANDOFF.md)를 먼저 읽는다. 다음 작업은 A1~A6의 기존 파일 기반 집계이며, 본문 작성·새 유료 실험·사람 판단은 아직 수행하지 않았다.

## 1. 제4장의 역할과 범위

제4장은 ‘원 KoBLEX ParSeR의 나머지 절차를 유지하고 CE 점수화만 Jev로 교체하면 어떤 차이가 관찰되는가’를 수치와 사례로 설명한다. 원 논문의 과거 점수를 재현했다고 주장하는 장이 아니다.

- 주 비교: 수정 CE `parser_ce_fixed` 대 Jev 교체 `parser_jev_fixed`.
- 재현 점검 참조: 공개 코드의 선택 인덱스 문제를 보존한 `parser_ce_raw`.
- 공식 한국어226문항 모두를 주 결과에 포함. 완전 매핑197문항·영향29문항은 보조 진단.
- 같은 예상 법령·BM25 후보·선택 및 생성 프롬프트·생성 모델·평가 기준을 사용한 대응 비교.
- 이번 실험은 이미 시험 결과를 확인한 뒤의 감사·재현이다. 모든 비교는 탐색적 해석으로 유지하며 사전확증 결과로 바꾸지 않는다.
- 현재 자료는 품질 비교에 충분하지만, 독립 온라인 지연·전체 운영비·필터링 효과·사람이 확인한 근거 지지율까지 완성된 자료는 아니다.

제3장과 중복하지 않기 위해 알고리즘·평가식·부트스트랩 정의는 제3장을 참조한다. 제4장에서는 비교에 필요한 조건, 결과, 차이의 불확실성, 예외와 오류 유형을 제시한다. 일반적 함의와 후속 연구 제언은 제5장 담당자에게 넘긴다.

## 2. 주어진 목차와 실제 실험의 정합성

| 항목 | 현재 실험과의 관계 | 집필 전에 팀과 맞출 사항 |
|---|---|---|
| 3.3.1 Vector Retrieval | 현재 본실험은 예상 법령별 BM25 검색 | ‘예상 법령 기반 BM25 Retrieval’ 등으로 수정 필요. Vector 결과를 현재 표에 붙이지 않음 |
| 3.3.3 Relevance Filtering/Reranking | 실행한 것은 점수화·재정렬, 그 뒤 같은 LLM 선택 | Filtering을 실제 수행한 것처럼 기술하지 않도록 범위 수정 |
| 4.2 / RQ1 | 수정 CE 대비 최종 선택 근거의 성능 비교 가능 | ‘검색 성능’의 측정 지점이 최종 근거 집합임을 명시. BM25 후보 검색 자체의 개선으로 쓰지 않음 |
| 4.3 / RQ2 정확도·지연 | 정확도 자료 있음, 유효한 독립 지연 비교 없음 | 정확도·하위집단 분석으로 제목/RQ 범위를 맞추거나 별도 지연 실험 후 완성 |
| 4.4 / RQ3 효율성·근거 충실도 | Token F1/LF-Eval 있음. 토큰량은 재집계 가능. 실제 제공 근거 지지는 사람 평가 전 | 자동 답변 평가와 근거 지지를 구분. ‘효율성 입증’은 보류하거나 자원 사용 기술통계로 범위 축소 |
| 부록 C Chunking | corpus 원 행 단위를 보존 | 새로운 문자 수 기반 chunking을 한 것으로 쓰지 않음 |

선택지 A — **현재 자료로 완결하는 권장 경로**:

- 4.1 실험 조건 요약.
- 4.2 Decision Model 교체에 따른 근거 선택 성능 변화.
- 4.3 CE 대비 성능 차이의 조건별 분석.
- 4.4 최종 답변의 자동 품질 평가와 자원 사용 특성.
- 4.5 오류 유형 및 사례 분석.
- RQ2·RQ3의 질문 표현도 1.3 담당자와 함께 실제 측정 범위로 맞춘다. 난이도별 분석을 새 RQ로 삼는다면 사후 탐색 질문임을 표시하고 사전 가설로 소급하지 않는다. 제4장만 제목을 바꿔 논문 전체의 RQ와 어긋나게 하지 않는다.

선택지 B — 원 목차를 그대로 유지:

- RQ2의 지연 부분은 추가 실험을 완료하기 전까지 미응답으로 둔다.
- RQ3는 자원 사용 재집계와 실제 사람 판단을 완료해야 한다. Filtering/품질 유지의 비열등성까지 질문에 포함한다면 별도 설계가 더 필요하다.
- 없는 수치를 채우거나 품질 실행의 캐시 시간을 지연 성능으로 전용하지 않는다.

권장 경로를 팀이 정하기 전에도 아래의 결과 근거 정리·표 설계·오류 분석 규칙 확정은 진행할 수 있다. 다른 장의 원고는 이번 작업에서 작성하지 않는다.

| 구분 | 내용 | 현재 할 수 있는 일 |
|---|---|---|
| 확정 결과 | 전체226문항의 근거 P/R/F1/EM, coverage, Token F1, LF-Eval, 대응 CI | 수치와 표 구조를 확정 가능 |
| 확정 보조 결과 | hop별 성능, 197/29 매핑 진단, 재현 오류 영향, 기술적 완료 수 | 기술통계와 제한된 해석을 계획 가능 |
| 기존 파일 재집계 필요 | 단계별 gold 잔존율, 문항별 승/무/패, 토큰·중복·선택 집합 크기, 오류 유형 빈도 | 모델 호출 없는 분석으로 산출 가능. 아직 집계 완료로 쓰지 않음 |

공식 source/hop 구분은 평가용이다. 온라인 점수화에 정답·gold 근거·정답 hop 수를 입력한 것으로 기술하지 않는다.

## 4. 확정 수치 원장

모든 품질 점수는0~1 원값을100배 표시한다. 차이와 CI는 반올림 전 원점수로 계산한다.

| 근거 Recall | 45.35 | 57.74 | 60.69 | +2.95점 | +0.39~+5.51 |
| 근거 EM | 17.70 | 27.88 | 29.65 | +1.77%p | −1.77~+5.19 |
| 모든 정답 근거 포함률 | 20.80 | 34.07 | 34.96 | +0.88%p | −2.90~+4.53 |

- 226문항,151개 source/gold 의존 그룹,대응 bootstrap10,000회,seed20261108.
- CI는 지표별 marginal percentile 구간이다. 다중 비교를 보정한 동시 구간이 아니다.
- `analysis.json`에서 모든 비교는 `confirmatory: false`다.
- Token F1은 percentile CI가0보다 높지만 centered-bootstrap 양측 p는약0.0525다. 두 계산이 검정–구간 쌍으로 완전히 일치하는 방법이 아니므로 ‘모든 지표 p<.05’로 요약하지 않는다. 집필에서는 사전에 고른 보고 원칙에 따라 점추정·CI를 중심으로 일관되게 설명한다.
- EM·모든 gold 포함률의 구간은0을 포함한다. 모든 측면의 일관된 우월성이나 동등성·비열등성을 주장하지 않는다.
- 공개 코드 참조 대비 수정 CE의 F1 +9.85점, LF-Eval +9.27점은 인덱스 수정 효과다. Jev 교체 효과와 합산하지 않는다.

## 5. 절별 집필 설계

### 4.1 실험 조건 요약 — 약0.30쪽

목적: 이후 결과를 어떤 조건 사이에서 읽어야 하는지 명확히 한다.

포함할 내용:
1. 전체226문항 대응 비교와 세 조건의 역할.
2. 주 비교가 수정 CE 대 Jev이고 공개 코드 오류 보존 CE는 재현 점검 참조라는 점.
3. 공통 예상 법령·BM25 후보·후속 LLM 선택·답변 생성·평가를 유지했다는 비교 통제.
4. 후보100개와 shortlist10개를 구분하고 최종 근거 수를5개로 고정하지 않았음을 명시.
5. 생성·선택과 judge의 GPT-4o snapshot, 한국어 CE/Jev 버전만 짧게 표시. revision 전체·장비·패키지는3.5/부록E로 보냄.
6. corpus 불일치29문항을 주 결과에서 제외하지 않았다는 분모 주석.

표1 계획: 조건명 / 점수화 모델 / 인덱스 처리 / 역할의3행 소표. 파이프라인 설명을 다시 길게 쓰지 않는다.

집필 전 확인:

- 제3장의 실제 절차가 BM25/원 행 단위/원 질문 입력과 맞는지.
- ‘공개 코드 문제’와 ‘원 논문의 실제 실행 문제’를 동일시하지 않는지.
- 기술적 완료 수가 법률적 정답 수로 표현되지 않는지.

### 4.2 Decision Model 적용에 따른 검색 성능 변화 — 약0.75쪽

목적: 주 비교의 최종 선택 근거 성능을 제시한다.

제시 순서:
1. F1을 중심 결과로 제시하고 Recall로 보완.
2. EM과 모든 gold 포함률을 함께 제시해 부분 회수 개선과 집합 완결성 개선을 구분.
3. 각 차이의 CI와 불확실성을 보고.
4. 공통 후보의 gold 가용성 및197/29 진단으로 결과의 범위를 제한.

사용 수치: 위 확정 수치 원장. Precision은 분량에 따라 부록D로 보낸다.

추가 재집계 계획:

- 각 문항의 BM25 후보 합집합 → scorer 상위10개 합집합 → 최종 선택 집합에서 gold 잔존 여부를 연결.
- 동일 공식 문자열의 중복을 제거한 평가 집합과 실제 입력 목록을 별도로 관리.
- 후보 합집합의 coverage는 필요조건의 상한으로 해석한다. pool마다 하나만 고르는 제약 때문에 모든 gold가 합집합에 있다고 실제로 모두 선택 가능하다는 뜻은 아니다.
- 단계별 결과를 만들더라도 모든 향상을 scorer 단독의 직접 효과로 서술하지 않는다. 현재 최종 결과는 바뀐 shortlist를 공통 LLM 선택기가 처리한 파이프라인 교체 효과다.

피할 주장:

- Vector 대비 우월성, reranker가 없는 BM25 최종 기준선 대비 향상. 해당 조건은 이번 본실험에 없음.
- 모든 질문/모든 난이도/모든 지표에서 개선.
- gold 외 근거를 곧바로 무관하거나 잘못된 법령으로 간주.

### 4.3 정확도·지연 비교 또는 조건별 성능 분석 — 약0.45쪽

현재 작성 가능한 정확도 부분:
-4.2의 전체 평균을 반복하지 않고 hop별·매핑 상태별 결과를 설명.
-1-hop의 감소와2/3-hop의 증가를 모두 포함.
-3-hop의 모든 gold 포함률은 두 조건 모두1/42=2.38%라는 점을 보조 진단에서 확인. 평균 F1 증가와 다중 근거 완결성은 구분.

- 문항별 F1 승/무/패를 추가 집계한다면 대응 비교와 허용오차를 사전에 정의. 이를 독립 표본의 성공률 검정처럼 다루지 않음.

지연 부분의 현재 상태:

- CE에는 pool별 wall-clock, Jev에는 캐시/문항 내 중복 재사용을 포함한 품질 실행 시간이 남아 있지만 측정 단위와 캐시 정책이 다르다.
- 생성에는 분당 토큰 제한 대기가 있으며 응답 캐시도 공유했다.
- 이 시간으로 평균·p95 속도 우월성을 계산하거나 이미 삭제한 다른 실험의 시간을 가져오지 않음.

지연 질문을 유지할 경우 필요한 별도 계획:
1. 측정 범위 확정: scorer+shortlist 출력까지인지, 후속 LLM 선택·생성까지 포함한 E2E인지 분리.
2. 같은 고정 후보를 사용하고 모델·API·장비·배치·동시성을 별도 잠금. CE MPS 대 원격 Jev의 배치 환경 비교로 명명.
3. 응답/점수 캐시를 끄고 pool 중복 처리 정책을 양쪽에 맞춤. 공유 결과를 온라인 실행 시간에 넣지 않음.
4. warmup 제외, 문항별 대응 반복, 방법 실행 순서 무작위화, 세션·네트워크·재시도·실패·의도적 rate 대기 기록.
5. 반복을 독립 질문으로 세지 않고 문항별 반복 평균에 대해 그룹 재표집. scoring-only와 E2E 결과를 별도 표로 보고.
6. 원 조건 전체226문항을3회 측정하면 Jev 후보 평가 기본량은47,800×3=143,400쌍에 warmup/재시도가 더해짐. 시간·예산을 먼저 점검. 표본 측정이라면 결과를 보고 고르지 않고 표본과 층화 비율을 고정.
7. 새 실행 ID/추가 프로토콜을 사용하고 기존 품질 잠금을 덮어쓰지 않음.

이 추가 실험은 현재 집필 계획의 실행 항목이 아니라, RQ2를 원래대로 유지할 때의 선행조건이다.

### 4.4 최종 답변의 효율성과 근거 충실도 — 약0.75쪽

현재 작성 가능한 자동 품질 부분:

- Token F1과 LF-Eval의 점추정·차이·CI.
- Token F1은 공식 공백 토큰 기반 문자열 중복 지표이며 생성 모델의 billable token과 다른 개념.
- LF-Eval은 정답 답변·정답 근거를 이용한 자동 법률 충실도 평가. 제공된 선택 근거가 모든 주장을 실제로 지지한다는 사람 판정과 다름.
- 같은 평가 대상 답변272쌍에서 LF 점수 동일함은 평가 일관성 점검으로 부록E에 배치 가능.
-800자 평가 규칙 및 전체 답변 사용 여부는3.4/부록E를 참조. 길이와 clip 영향은 필요하면 기존 파일로 점검.

현재 파일만으로 추가 가능한 자원 사용 분석:
1. 실제 선택 목록의 근거 수, 고유 canonical 근거 수, 중복 비율.
2. 선택 문맥 토큰 수: 정확히 생성기에 전달한 문자열과 고정 tokenizer로 산출. system/few-shot/질문을 포함한 전체 입력량과 문맥만의 토큰량을 구분.
3. `generation_trace.usage`의 입력/출력 token 기술통계. 모든 조건226행에서 사용량 필드가 확인됨.
4. 평균뿐 아니라 중앙값·IQR, 문항별 대응 차이. 원 자료 해시와 집계 규칙을 기록.
5. 품질 지표와 입력량의 관계는 기술통계로만 보고. 긴 문맥이 원인이라거나 최적 효율을 달성했다고 주장하지 않음.

구조적으로 이미 확인한 사실:

- 최종 선택 목록 길이는 세 조건 모두1개37문항/2개135/3개46/4개7/5개1로 동일. 합계478개.
- Jev가 Filtering으로 문서 수를 줄인 실험이 아니다. 고유 집합 크기나 문맥 길이가 다르다면 선택한 법령·중복의 차이로 설명해야 함.
- 생성 응답의 실행 캐시 표시는 공개 코드 CE0/수정 CE72/Jev122행. 캐시된 행의 사용량은 동일 입력의 요구량을 기술하는 데 쓸 수 있지만, 해당 조건이 실제로 새로 청구된 양으로 합산하지 않음.

비용 보고 원칙:

- 실험 전체 누적 지출, 조건별 논리적 입력량, 독립 서비스 실행을 가정한 비용 추정은 별개.
- judge·준비·공통 생성·재시도 비용을 실제 사용자의 온라인 질의 비용에 섞지 않음.
- 로컬 CE 장비·전력·네트워크·운영 단가가 없으므로 전체 비용 우월성을 확정하지 않음.
- 전체 실험 비용과 미정산 예약액은 재현 운영 정보로 부록E에 배치.
- FR/문턱값/비열등성 실험이 없으므로 ‘품질 유지하며 비용 절감’이라는 결론을 만들지 않음.

실제 근거 충실도에 필요한 사람 평가:

- 기존60문항×3조건,2명 독립 검토. 샘플과 방법 블라인드 유지.
- 정확성, 선택 근거 지지, unsupported legal claim을 구분.
- 제출 검증 → 최초 독립 일치도 → 불일치 조정 → 최종 값의 조건별 집계 순서.
- 현재 판단0개다. 사람 정확도·지지율·kappa·모델과의 상관을 숫자로 채우지 않음.
- 시간이 맞지 않으면 자동 평가의 범위를 명확히 하고 실제 제공 근거 지지는 미검증으로 남김.

### 4.5 오류 사례 분석 — 약0.75쪽

목적: 개선되는 경우와 남은 실패를 양쪽 조건에 대해 설명한다. 유리한 사례만 모으지 않는다.

대상 구분:

- 주 분석은 수정 CE/Jev. 공개 코드 인덱스 문제는 별도 재현 오류로 분리.
- strict gold 일치 오류, 기술 실패, 법률적 오답, 제공 근거 미지지는 서로 다른 분류.
- LF judge의 reason은 사례 후보를 찾는 보조 자료이며 사람의 최종 판정으로 사용하지 않음.

자동으로 분류할 단계별 상태:
1. corpus에 exact gold가 없음.
2. corpus에는 있으나 공통 BM25 후보에 없음.
3. BM25 후보에는 있으나 scorer shortlist에 없음.
4. shortlist에는 있으나 최종 선택에 없음.
5. 모든 gold를 선택했으나 자동 답변 점수가 낮음.
6. gold 외 근거를 추가해 precision/EM이 낮아짐.

이 상태들은 법적 오류 진단과 동일하지 않다. 특히4번은 pool당 하나 선택 제약과 금지된 oracle 선택을 고려해 ‘LLM 선택 실패’로 단정하지 않고 먼저 관측 상태로 기록한다.

분모와 중복 처리:

- 개별 gold의 탈락 단계를 세면 문항별 gold 출현 단위를 분모로 하고 고유386개와 혼동하지 않음.
- 문항 수준에서는 여러 원인이 동시에 생길 수 있으므로 다중 라벨이면 합계가226을 넘을 수 있음을 표시.
- 배타적인 대표 원인을 원하면 우선순위를 집계 전에 고정. 유리한 원인으로 임의 분류하지 않음.

대표 사례 선정 규칙:

- Jev 개선 / CE 우세 / 양쪽 실패 / 근거 지표와 답변 지표가 엇갈림의 네 묶음을 먼저 정의.
- hop·매핑 상태를 함께 고려. 현재 사람 평가60문항의 샘플을 사후 교체하지 않음.
- 큰 차이만 뽑지 않고 각 묶음의 중앙적 사례를 우선, 동률은 query_id 순서. 표본이 없으면 없는 것으로 기록.
- 본문은3개 내외로 제한: Jev 개선1, CE 우세1, 공통 실패 또는 지표 불일치1. 나머지는 부록D.
- 각 사례에 query_id, 공식 hop, gold 식별자, 선택 근거 차이, F1/LF 변화, 관측된 탈락 단계, 법률 검토 상태를 남김.
- 본문은 질문 요약과 핵심 근거 차이만, 원 질문·긴 조문·전체 답변은 부록A/D.
- 의미상 적절한 대체 근거, 예외·준용 누락, 법률 결론의 오류 여부는 전문가 확인 후 명명. 공식 gold는 사후 변경하지 않음.

기본 분량:4.1 0.30 /4.2 0.75 /4.3 0.45 /4.4 0.75 /4.5 0.75쪽 =3.00쪽.

권장 구성:

## 9. 집필 준비 순서와 완료 판정

1. RQ와 목차의 불일치를 팀과 정리한다. 현재 자료 경로로 쓸지 추가 지연/사람 평가까지 기다릴지 확정.
