# arXiv 실험 결과 절의 서술 방식 검토

검토일: 2026-11-09. 목적은 제4장의 한국어 학술 문체를 다듬는 것이다. 모델 재훈련이나 새로운 실험을 수행한 작업은 아니다. 아래 논문의 문장을 번역하거나 모방해 원고에 옮기지 않고, 문단 전개와 증거 제시 방식을 참고했다.

## 자료와 검토 범위

법률 QA 2편, 검색·재정렬·생성 QA 4편, 인용·문맥 이용·평가 4편을 목적에 맞게 선정했다. 체계적 문헌고찰이나 분야 전체의 대표 표본은 아니다. **10편의 PDF 원문 182쪽을 보관하고, 아래 결과 관련 30쪽을 읽었다.** 각 논문에서 대표 결과 페이지 1쪽씩을 렌더링해 표·그림과 본문의 배치도 확인했다. 초록만으로 문체를 분석한 자료는 없다.

- [수집 원장](papers-manifest.json): 제목, arXiv 버전, 원문 URL, SHA-256, 파일 크기, 전체 페이지 수, 읽은 페이지.
- [원문과 페이지별 추출 텍스트](papers/): 원본 PDF와 `.txt`. 페이지 표시는 PDF의 물리적 순서이며 1부터 센다.
- [색인 코드](index_papers.py): PDF 안의 arXiv 표기로 버전을 확인하고 텍스트와 원장을 생성한다. 최초 다운로드는 버전 없는 URL로 요청했고, 원장에 실제 수집본의 버전 URL을 함께 기록했다.
- 레이아웃 확인 이미지: `tmp/pdfs/chapter4/style-reference-pages/`. 본문 이해는 추출 텍스트, 표·그림 배치 확인은 렌더링 이미지를 사용했다.

## 논문별 관찰과 적용

### 1. KoBLEX

[KoBLEX: Open Legal Question Answering with Multi-hop Reasoning](https://arxiv.org/abs/2509.01324v1), v1. 읽은 범위: PDF 7–9쪽, §6 Experiments, §7 Results, §8 Analyses. 레이아웃 확인: 8쪽.

Table 2에서 근거 F1/EM과 답변 Token F1/LF-Eval을 구획하고, §7은 방법별 모든 셀을 열거하는 대신 주요 비교의 차이를 고른다. §8은 Reasoning Depth, Ablation Study, Efficiency, Effect of Retriever Type 등 분석 질문별로 나눈다. Figure 6의 hop 분석은 전체 표와 다른 역할을 맡는다. 9쪽에서는 후보 범위를 늘려도 생성 지표가 일관되게 증가하지 않는 결과를 명시한다.

적용: 4.2의 공통 성능 표를 4.4가 함께 참조하고, 4.3은 전체 평균을 반복하기보다 조건별 예외를 설명한다. 적용하지 않을 점: 원문의 모든 조건 우월성이나 생성 토큰 수에 근거한 효율성 결론을 현재 재현 실험에 가져오지 않는다. 원 논문의 표 점수를 현재 결과와 혼합하지 않는다.

### 2. LegalBench-RAG

[LegalBench-RAG: A Benchmark for Retrieval-Augmented Generation in the Legal Domain](https://arxiv.org/abs/2408.10343v1), v1. 읽은 범위: PDF 5–8쪽, §3.3–3.5, §4, §5.1–5.2. 레이아웃 확인: 7쪽.

§4.2와 7쪽은 데이터셋별 동일 가중 집계를 명시한다. §5.1은 reranker가 기대와 달리 낮은 성능을 보인다는 결과를 숨기지 않고, §5.2는 데이터셋별 차이를 이어 설명한다. 원문의 도메인 적합성 설명에는 가능성을 나타내는 표현이 붙는다. 다만 §5.1의 RCTS 우세라는 포괄적 문장과 Table 4/5의 ALL recall 등은 지표와 k에 따라 다르게 읽힐 수 있다. 원문의 요약 자체를 검증된 일반 법칙으로 받아들이지 않았다.

적용: 평균 방식과 분모를 짧게 명시하고, 1-hop 감소와 입력량 증가를 결과의 일부로 직접 쓴다. 적용하지 않을 점: 일부 수치의 우세를 모든 지표·설정의 우월성으로 확대하거나, 도메인 특성을 측정 없이 원인으로 확정하는 문장.

### 3. RAG

[Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401v4), v4. 읽은 범위: PDF 5–6쪽, §4.1–4.4. 레이아웃 확인: 6쪽.

§4.2는 비교 모델과 Bleu/Rouge-L 차이를 먼저 제시한 뒤 gold passage 접근 조건을 설명한다. Table 2의 별표와 밑줄은 비교 조건 차이를 독자가 확인할 수 있게 한다. §4.3은 자동 평가, 실제 사람 평가, 생성 사례를 다른 증거로 제시한다. 사례 설명은 실제 출력 토큰과 해당 문서의 관계를 구체적으로 짚는다.

적용: 절의 첫 문장에 관찰된 결과를 두고, 바로 필요한 비교 조건을 붙인다. 사례는 ‘선택 조문 → 답변 표현 → 자동 지표 변화’ 순서로 설명한다. 적용하지 않을 점: 다른 연구의 사람 평가를 현재 실험의 근거로 대신 쓰거나, 사례 하나에서 일반적인 인과 효과를 확정하는 서술.

### 4. DPR

[Dense Passage Retrieval for Open-Domain Question Answering](https://arxiv.org/abs/2004.04906v3), v3. 읽은 범위: PDF 5–7쪽, §5.1–5.4 및 §6 도입. 레이아웃 확인: 5쪽.

§5.1은 주 결과를 설명하면서 곧바로 SQuAD 예외를 밝히고, Natural Questions top-20 수치 한 쌍으로 차이의 크기를 예시한다. 뒤의 SQuAD 원인 설명은 추측임을 표시한다. §5.2는 Sample efficiency, In-batch negative training 등 질문별 문단으로 나눈다. §5.4는 온라인 검색 속도와 인덱스 구축 비용을 분리하고 장비와 관측 단위를 제시한다.

적용: 전체 평균과 하위집단 예외를 함께 설명한다. 자원 사용은 관측한 단위와 측정 범위부터 분명히 한다. 적용하지 않을 점: 토큰량을 지연 또는 전체 비용과 같은 지표로 취급하는 서술.

### 5. Fusion-in-Decoder

[Leveraging Passage Retrieval with Generative Models for Open Domain Question Answering](https://arxiv.org/abs/2007.01282v2), v2. 읽은 범위: PDF 3–5쪽, §4 Experiments. 레이아웃 확인: 4쪽.

주 비교는 Table 1, 문서 수에 따른 변화는 Figure 3, 학습 문서 수와 자원 간 관계는 Table 2로 나눈다. 5쪽은 학습 때 사용하는 문서 수와 평가 때 사용하는 문서 수를 구분한 다음 성능·GPU hours를 비교한다. 조건 설명이 자원 해석에 직접 연결된다.

적용: 4.2는 주 비교, 4.3은 조건별 변화, 4.4는 입력 요구량으로 역할을 분명히 한다. 적용하지 않을 점: 현재 측정하지 않은 계산 시간이나 GPU 비용을 토큰량으로 대체하는 추정.

### 6. RankGPT

[Is ChatGPT Good at Search? Investigating Large Language Models as Re-Ranking Agents](https://arxiv.org/abs/2304.09542v3), v3. 읽은 범위: PDF 5–7쪽, §6.1–6.6. 레이아웃 확인: 5쪽.

§6.2는 TREC/BEIR의 평균 차이를 제시한 뒤 Mr.TyDi에서 Bengali, Telugu, Thai의 열세를 별도로 적는다. Table 1 주석은 BEIR의 GPT-4 조건이 ChatGPT가 재정렬한 top-30을 사용한다는 차이를 명시한다. §6.5는 재정렬 반복이 nDCG@10을 높여도 nDCG@1을 낮추는 지표 간 상충을 기록한다.

적용: 개선을 특정 평가 범위에 묶어 쓰고, 성능 감소와 지표 불일치를 같은 수준의 결과로 다룬다. 비교 조건과 단위는 표 주석에서 확인할 수 있게 한다. 적용하지 않을 점: 평균 순위를 모든 문항의 우월성으로 바꾸는 표현.

### 7. ALCE

[Enabling Large Language Models to Generate Text with Citations](https://arxiv.org/abs/2305.14627v2), v2. 읽은 범위: PDF 6–8쪽, §5.1–5.4와 §6 도입. 레이아웃 확인: 7쪽.

§5.1은 정확성 향상과 인용 품질 하락을 함께 제시하고, CLOSED BOOK+POST CITE의 높은 correctness가 좋은 citation quality를 뜻하지 않는다고 구체화한다. §5.3은 검색 recall과 최종 답변 품질 사이의 차이를 Figure 4로 설명한다. §6은 자동 점수와 별도로 수행한 사람 평가의 대상과 질문을 명시한다.

적용: 근거 F1, 정답 기준 LF-Eval, 제공 근거의 주장 지지를 각각의 평가 대상으로 쓴다. 사례 C는 지표 불일치의 관측으로 설명한다. 적용하지 않을 점: 현재 사람 평가가 없는 상태에서 자동 지표를 실제 법률적 정오·주장 지지 판정으로 확장하는 것.

### 8. Lost in the Middle

[Lost in the Middle: How Language Models Use Long Contexts](https://arxiv.org/abs/2307.03172v3), v3. 읽은 범위: PDF 4–7쪽, §2.2–2.3, §3.1–3.2, §4 도입. 레이아웃 확인: 5쪽.

§2.3은 정보 위치에 따른 U자형 패턴을 먼저 진술하고, Figure 5와 closed-book 기준선 수치로 뒷받침한다. 긴 context window를 가진 모델이 반드시 정보를 더 잘 활용하는 것은 아니라는 결과를 별도 문단으로 제시한다. §3.2는 같은 경향과 Claude의 거의 완벽한 수행이라는 예외를 함께 적는다. §4의 기제 설명은 추가 분석과 가설로 구분된다.

적용: 그래프를 소개하는 문장보다 관찰된 패턴을 먼저 쓴다. 평균 토큰량과 품질의 동반 변화를 인과 관계로 쓰지 않는다. 적용하지 않을 점: 이 논문의 위치 효과를 측정하지 않은 현재 실험의 실패 원인으로 가져오는 것.

### 9. Ragas

[Ragas: Automated Evaluation of Retrieval Augmented Generation](https://arxiv.org/abs/2309.15217v2), v2. 읽은 범위: PDF 4–5쪽, §4 WikiEval, §5 Experiments. 레이아웃 확인: 5쪽.

§5는 모델과 사람이 같은 답변을 선호한 비율이라는 관측 단위를 먼저 정의한다. Table 1의 세 평가 차원을 모두 같은 수준으로 성공했다고 쓰지 않고, faithfulness의 높은 일치와 context relevance의 상대적 어려움을 나눈다. 사람 평가 표본을 실제로 만든 연구라는 점도 결과 해석의 전제다.

적용: 각 지표가 무엇을 측정하는지 짧게 밝히고, 지표마다 다른 결과를 보존한다. 적용하지 않을 점: Ragas의 사람 일치도를 LF-Eval 또는 현재 자료의 검증값으로 전용하는 것.

### 10. RAGChecker

[RAGChecker: A Fine-grained Framework for Diagnosing Retrieval-Augmented Generation](https://arxiv.org/abs/2408.08067v2), v2. 읽은 범위: PDF 7–9쪽, §4.2 후반, §4.3–4.4. 레이아웃 확인: 8쪽.

Table 3은 전체 결과와 retriever/generator 진단을 나눈다. §4.3은 전체 성능 이후 문맥 이용·잡음 민감도 등 단계별 관찰로 설명을 좁힌다. §4.4는 context 증가가 faithfulness와 noise sensitivity에 서로 다른 영향을 주는 수치들을 병기한다. 8쪽 첫 문장은 자동 평가와 사람 판단의 간격도 남긴다.

적용: 4.2의 최종 결과를 4.5의 corpus→BM25→shortlist→선택 관측으로 설명하되, 각 단계에 맞는 단위와 분모를 쓴다. 적용하지 않을 점: 상관이나 단계별 잔존 차이만으로 재정렬기의 독립 인과 효과를 확정하는 것.

## 제4장에 적용할 문체 원칙

1. **결과를 문단 첫머리에 둔다.** ‘분석하였다/제시하였다’로 시작하는 도입을 줄이고, 어떤 지표가 어느 조건에서 어떻게 달랐는지 먼저 쓴다. 4.1의 조건 설명은 예외다.
2. **한 문단에 한 가지 비교 질문을 둔다.** 평균 근거 성능, 완전 회수, hop 차이, 매핑 차이, 답변 품질, 입력량, 단계별 탈락, 개별 사례를 분리한다.
3. **핵심 차이를 해석한다.** 표의 모든 셀을 순서대로 읽는 문장을 줄인다. 중요한 점수·차이·구간과 불리한 수치는 보존한다.
4. **관찰과 설명의 강도를 맞춘다.** 관측값에는 ‘높았다/낮았다/남았다’를, 설명에는 ‘시사한다/관련된다/가능성이 있다’를 쓴다. 새 검정 없이 ‘유의하다’, ‘입증했다’, ‘원인이다’를 추가하지 않는다.
5. **한계를 관련 결과 바로 뒤에 둔다.** EM/완전 회수의 불확실성, 1-hop 감소, 사람 평가 부재, 토큰과 비용의 차이는 해당 문단에서 한 번 분명히 적는다. 각 절 말미에 같은 금지 문장을 반복하지 않는다.
6. **단위와 평가 대상을 고정한다.** 226문항의 평균, 443건의 문항별 gold 출현, 386개의 전역 고유 gold, 사용량 토큰을 혼용하지 않는다. 차이는 반올림 전 값을 유지한다.
7. **사례는 선택 차이와 출력 차이를 연결한다.** A는 개선, B는 악화, C는 지표 불일치의 관측이다. 법률적 정오와 gold 외 근거의 타당성은 전문가 검토 전 상태를 유지한다.
8. **검토 기록과 논문 문장을 구별한다.** 원자료 경로·사례 선정 규칙·미실행 항목은 재현 기록에 남기되, 본문은 독자가 결과를 이해하는 데 필요한 설명을 중심으로 쓴다.

영문 논문의 강조형 소제목·홍보성 수식어를 그대로 한국어로 옮기지 않았다. 현재 3쪽 내외의 분량에서는 소제목을 추가하기보다 문단 첫 문장을 명확히 하는 쪽을 택했다. 이 문헌들은 **문체 참고 자료**이며, 현재 실험 점수의 출처를 대체하지 않는다.
