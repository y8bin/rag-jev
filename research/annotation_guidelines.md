# 법률 평가 지침 — 파일럿 검토용 v2

상태: **DRAFT**. 아래는 구현과 일치하는 운영 초안이다. 법률 평가자 2명과 조정 담당이 실제 원문으로 교육·독립 판정·불일치 조정을 한 뒤 버전과 확정일을 기록한다. 예시는 설명용 가상 문장이다.

## 질문과 충분 근거

1. 적용 시점·관할·사실관계·필수 법적 요건을 확인한다. 기준 답변에 핵심 결론, 필수 요건, 허용되는 대체 결론·표현을 적는다. 복수 해석/사실 부족은 보류·제외 이유를 기록한다.
2. 직접 조문, 사실 적용, 예외·요건, 복수 근거, 코퍼스 근거 부족 유형을 구분한다. 작성 출처와 원문 복사 여부는 질문 sidecar에 기록한다.
3. 각 필수 주장에 `evidence_units`를 연결한다. 가능한 한 정규화 문서의 Python 문자 구간 `[start,end)`를 쓴다. 여러 청크가 필요하면 구간 전체가 이어져야 회수다. `chunk_ids` 목록은 대체 청크 중 하나만 있으면 회수되는 표현이다.
4. 답 전체를 지지하는 최소 조합을 `sufficient_sets`로 적는다. 본문 U1과 예외 U2가 모두 필요하면 `[["U1","U2"]]`다. 대체 완전 조합은 별도 집합으로 적는다.
5. 근거 부족은 이 코퍼스에서 충분한 근거를 찾지 못했다는 판정이다. 넓은 검색·원문 탐색 범위, 검색어·날짜·평가자·이유를 기록한다. 근거를 인위적으로 제거한 문항은 별도 진단으로 표시한다.
6. answerability와 충분 집합을 독립 이중 판정한다. 기존 gold 밖의 대체 법령·판례도 lexical-pool·원문 탐색으로 검토하고 변경 이력을 남긴다. 방법별 시험 점수 공개 전에 시험 후보 라벨을 동결한다.

## 후보 0/1/2

| 등급 | 판정 | 예시 |
|---|---|---|
| 2 | 핵심 또는 필요한 하위 주장을 직접 지지 | 신청 기한 조문, 필수 예외 조문. 혼자 답 전체에 충분할 필요는 없음 |
| 1 | 관련 배경이며 해당 요건·결론을 직접 입증하지 못함 | 같은 제도의 목적·정의만 설명 |
| 0 | 부적합 | 다른 관할·시점·사실관계·쟁점, 단어만 일치 |

미판정은 `null`이며 0이 아니다. 공통 K 후보 전체를 판정하고, 등급 2의 충분성과 충분 집합을 구별한다. 경계 사례는 실제 원문 위치와 판정 이유를 추가한다.

## 답변 v2 양식

`export-annotations --kind answers`의 `tasks.jsonl`만 평가자에게 전달한다. 방법·점수·순위·`private_mapping.json`은 제공하지 않는다. 두 평가자는 동일 task ID를 각자 복사한 파일에서 독립 판정한다. 질문·답변·근거 본문을 수정하지 않는다.

| 필드 | 입력 규칙 |
|---|---|
| `annotation_schema_version` | 2 그대로 유지 |
| `correctness` | 핵심 결론·필수 요건·적용 시점·사실관계가 맞으면 true. 근거 부족 질문에서는 실제로 적절하게 보류했는지도 확인 |
| `core_supported` | 핵심 결론과 필수 요건이 제공 근거로 지지되는지 전체 검토 |
| `claims_complete` | `answer`와 `rationale`의 모든 검증 가능한 주장이 생성된 `claims`에 포함되면 true |
| `omitted_claims` | 누락된 실제 주장 문장 목록. 완전하면 `[]`. 누락이 있으면 `claims_complete=false` |
| `claim_labels[].is_core` | 핵심 결론·필수 요건·예외·적용 판단에 필요한 주장은 true, 부수적 배경은 false |
| `claim_labels[].support` | 제공 근거가 지지하면 supported, 지지가 없으면 unsupported, 반대 근거면 contradicted |
| `claim_labels[].citations[].supported` | 이 ID가 연결된 해당 주장을 실제 지지하면 true. ID가 존재하는 것만으로 true가 아님 |
| `reviewer`, `notes` | 평가자, 모호성·불일치·보류 값과 실제 내용의 불일치·조정 이유 |

누락 문장을 발견하면 답변/claims를 수정하지 않고 누락 목록에 적는다. 새 양식에는 모든 `is_core`와 완전성 판정이 필수다. 누락 주장 자동 탐지는 구현하지 않았으며 사람의 전체 텍스트 검토를 요구한다.

## 지표와 판정 예시

`grounded_correct`는 answerable 문항에서 correctness·core_supported·claims_complete가 모두 true이고, 보류하지 않았으며, 최소 하나의 핵심 주장이 있고, 모든 핵심 주장이 지지되고 각각 제공된 ID의 지지 인용을 가져야 1이다. 핵심 주장에 올바른 지지 인용이 하나 이상 있는지를 요구하며, 인용 전체의 정확성은 별도 지표로 보고한다.

`strict_grounded_correct`는 추가로 모든 생성 주장과 모든 인용의 지지를 요구한다. 전체 인용 목록에 미판정/잘못된 ID가 있거나 부수 주장에 지지가 없으면 0이다. v2에서는 주장 완전성도 필요하다. 기존 v1 판정은 strict 보조 지표만 산출할 수 있고 새 주 지표는 미확인이다. 기존 결과를 재평가하려면 새 디렉터리로 v2 양식을 다시 내보낸다.

예: 핵심 기한 답은 올바른 인용으로 지지되지만 부수 배경 문장은 지지가 없는 경우, correctness가 true라는 법률 판정을 전제로 primary=1, strict=0일 수 있다. 필수 예외를 누락하면 correctness=false다. rationale에 검증 가능한 주장을 적고 claims에서 빼면 completeness=false이며 두 지표 모두 0이다. 핵심 주장에 제공되지 않은 ID만 연결하면 primary=0이다.

답할 수 있는 질문의 보류·기술 실패는 주 지표 실패다. 주장 없는 응답의 지지율은 N/A이고 answerable 주 지표를 통과하지 못한다. `appropriate_abstention`/`over_abstention`은 현재 모델의 abstained 표식 기반 보조 지표이므로 실제 보류 타당성과 값·내용 일치는 별도 사람 검토·notes에서 확인한다.

## 일치도와 보관

`agreement`는 후보의 비가중·선형·제곱 가중 kappa와 답변 정답·핵심 지지·주장 지지·인용 지지·핵심 분류·완전성 일치도를 제공한다. 원본 두 판정, 공통/단독 판정 ID, conflicts, 최종 조정 파일을 보존한다. 주장·인용 단위 kappa는 기술 통계이며 동일 답변 내 상관을 반영한 신뢰구간은 아니다.

조정은 자동 다수결로 하지 않는다. 조정 담당이 원문을 확인해 최종값과 이유를 기록한다. 후보당·답변당·조정당 시간과 교육 전후 변경량을 실제 파일럿에서 측정한다.
